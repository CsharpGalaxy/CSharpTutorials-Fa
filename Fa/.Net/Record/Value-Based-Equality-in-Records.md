# آموزش کامل Value-Based Equality در Recordهای سی‌شارپ (C#)

درک مفهوم «برابری» (Equality) یکی از مهم‌ترین مباحث در برنامه‌نویسی شی‌گرا است. با معرفی **Record**ها در سی‌شارپ ۹ و توسعه آن‌ها در نسخه‌های بعدی، نحوه برخورد زبان با برابری تغییرات بنیادینی کرد. 

در این آموزش جامع، از مفاهیم پایه شروع کرده و به بررسی عمیق برابری در Recordها می‌پردازیم.

---

## بخش اول: مفاهیم پایه برابری (Equality)

برای درک Recordها، ابتدا باید دو مفهوم کلیدی را بشناسیم:

### ۱. برابری مرجع (Reference Equality)
وقتی دو متغیر به **یک مکان واحد در حافظه (RAM)** اشاره می‌کنند، می‌گوییم برابری مرجع دارند. 
* **مثال روزمره:** شما و برادرتان دو ریموت کنترل متفاوت در دست دارید، اما هر دو دارید **یک تلویزیون** را کنترل می‌کنید.
* در سی‌شارپ، این حالت پیش‌فرض برای **کلاس‌ها (Classes)** است.

### ۲. برابری مقدار (Value Equality)
وقتی دو متغیر در **مکان‌های متفاوتی از حافظه** قرار دارند، اما **داده‌ها و مقادیر درون آن‌ها دقیقاً یکسان** است.
* **مثال روزمره:** دو اسکناس ۱۰ دلاری. از نظر فیزیکی دو کاغذ متفاوت هستند (مکان حافظه متفاوت)، اما ارزش و مقدار آن‌ها یکی است.
* در سی‌شارپ، این حالت پیش‌فرض برای **ساختارها (Structs)** و **انواع اولیه (مثل int, string)** است.

---

## بخش دوم: برابری در انواع مختلف (Class و Struct)

### کلاس معمولی (Class)
در یک کلاس معمولی، اپراتور `==` و متد `Equals` به صورت پیش‌فرض **برابری مرجع** را بررسی می‌کنند. اگر بخواهید دو شیء از یک کلاس را بر اساس مقادیرشان مقایسه کنید، باید خودتان متدهای `Equals` و `GetHashCode` را Override کرده و اپراتورهای `==` و `!=` را Overload کنید.

### ساختار (Struct)
در یک Struct، برابری پیش‌فرض **برابری مقدار** است. کامپایلر سی‌شارپ به صورت خودکار تمام فیلدهای Struct را با هم مقایسه می‌کند. 
* **نکته منفی:** این مقایسه پیش‌فرض با استفاده از *Reflection* انجام می‌شود که از نظر پرفورمنس کند است. بنابراین در Structها همیشه توصیه می‌شود که `Equals` و `GetHashCode` را به صورت دستی پیاده‌سازی کنید.

## بخش سوم: ورود Recordها به میدان

رکوردها (Records) در سی‌شارپ برای مدل‌سازی داده‌ها طراحی شده‌اند. هدف اصلی آن‌ها این است که **برابری مقدار (Value Equality)** را به صورت پیش‌فرض و با بالاترین پرفورمنس ارائه دهند.

ما دو نوع رکورد داریم:
1. **`record class`** (یا به اختصار `record`): یک کلاس است که روی Heap تخصیص می‌یابد.
2. **`record struct`**: یک ساختار است که معمولاً روی Stack (یا به صورت inline) تخصیص می‌یابد.

### مثال: چگونه دو شیء متفاوت از نظر Record برابرند؟

```csharp
// تعریف یک record class
public record Person(string FirstName, string LastName, int Age);

// تعریف یک record struct
public record struct Point(int X, int Y);
```

حالا دو نمونه (Instance) متفاوت می‌سازیم:

```csharp
Person person1 = new("Ali", "Rezaei", 30);
Person person2 = new("Ali", "Rezaei", 30);

Point p1 = new(10, 20);
Point p2 = new(10, 20);

// بررسی برابری
Console.WriteLine(person1 == person2); // خروجی: True
Console.WriteLine(p1 == p2);           // خروجی: True
```
با اینکه `person1` و `person2` در آدرس‌های کاملاً متفاوتی در حافظه Heap ساخته شده‌اند، اما چون مقادیر Propertyهای آن‌ها یکسان است، رکورد آن‌ها را **برابر** می‌داند.

## بخش چهارم: متدها و اپراتورهای کلیدی در Record

وقتی شما یک Record تعریف می‌کنید، کامپایلر سی‌شارپ به صورت خودکار (Synthesize) موارد زیر را برای شما تولید می‌کند:

### ۱. متد `Equals` و اینترفیس `IEquatable<T>`
رکوردها به صورت خودکار اینترفیس `IEquatable<T>` را پیاده‌سازی می‌کنند. این یعنی متد `Equals(T other)` با تایپ مشخص (Type-safe) تولید می‌شود که از باکس شدن (Boxing) جلوگیری کرده و پرفورمنس را به شدت افزایش می‌دهد.

### ۲. متد `GetHashCode`
کامپایلر یک متد `GetHashCode` تولید می‌کند که بر اساس مقادیر تمام Propertyهای رکورد، یک کد هش (Hash Code) یکتا می‌سازد. این موضوع باعث می‌شود رکوردها به بهترین شکل در دیکشنری‌ها (`Dictionary`) و مجموعه‌های هش‌بیس (`HashSet`) کار کنند.

### ۳. اپراتورهای `==` و `!=`
کامپایلر به صورت خودکار این اپراتورها را Overload می‌کند تا به جای بررسی آدرس حافظه، **مقادیر** را مقایسه کنند.

## بخش پنجم: تفاوت حیاتی `ReferenceEquals` و `==`

این بخش یکی از مهم‌ترین مفاهیم برای درک عمیق Recordهاست.

* **`a == b`**: از اپراتور Overload شده استفاده می‌کند. در Recordها، این اپراتور **برابری مقدار (Value Equality)** را بررسی می‌کند.
* **`ReferenceEquals(a, b)`**: یک متد استاتیک از کلاس `Object` است که **فقط و فقط** بررسی می‌کند آیا هر دو متغیر به **یک آدرس حافظه** اشاره می‌کنند یا خیر (برابری مرجع). این متد را نمی‌توان Override کرد.

### مثال عملی:

```csharp
Person ali1 = new("Ali", "Rezaei", 30);
Person ali2 = new("Ali", "Rezaei", 30);
Person ali3 = ali1; // ali3 دقیقاً به همان آدرس حافظه ali1 اشاره می‌کند

Console.WriteLine(ali1 == ali2);                 // True (چون مقادیرشان یکی است)
Console.WriteLine(ReferenceEquals(ali1, ali2));  // False (چون دو شیء مجزا در Heap هستند)

Console.WriteLine(ali1 == ali3);                 // True
Console.WriteLine(ReferenceEquals(ali1, ali3));  // True (چون دقیقاً یک شیء هستند)
```

## بخش ششم: Record Equality چگونه Propertyها را مقایسه می‌کند؟

طبق **C# Specification**، وقتی کامپایلر می‌خواهد برابری دو Record را بررسی کند، از الگوریتم زیر استفاده می‌کند:

1. **بررسی Reference:** ابتدا چک می‌کند آیا هر دو به یک آدرس اشاره می‌کنند؟ اگر بله، سریعاً `true` برمی‌گرداند.
2. **بررسی Null:** اگر یکی null و دیگری غیر null باشد، `false` برمی‌گرداند.
3. **بررسی Type:** آیا هر دو دقیقاً از یک نوع (Type) هستند؟ (در اینترفیس‌ها و ارث‌بری دقت کنید).
4. **مقایسه تک تک اعضا:** کامپایلر تمام **Instance Fieldها** و **Propertyهای غیر استاتیک** را مقایسه می‌کند.

### نکات بسیار مهم در مقایسه Propertyها:
* **مقایسه عمیق (Deep Comparison) برای رکوردهای تودرتو:** اگر یک Property از نوع یک Record دیگر باشد، متد `Equals` آن رکوردهای داخلی نیز فراخوانی می‌شود.
* **آرایه‌ها و کالکشن‌ها (Gotcha):** اگر Property شما از نوع `List<T>` یا `Array` باشد، رکورد برای آن‌ها از **برابری مرجع** استفاده می‌کند، نه برابری مقدار! (مگر اینکه از `EqualityComparer` سفارشی استفاده کنید).

```csharp
public record Student(string Name, List<int> Scores);

var s1 = new Student("Ali", new List<int> { 18, 19 });
var s2 = new Student("Ali", new List<int> { 18, 19 });

Console.WriteLine(s1 == s2); // خروجی: False !!! 
// زیرا List<int> در s1 و s2 دو شیء متفاوت در حافظه هستند.
```

## بخش هفتم: جدول مقایسه نهایی

در اینجا تفاوت رفتار کلاس‌ها، ساختارها و رکوردها را در یک نگاه مرور می‌کنیم:

| ویژگی | Class معمولی | Struct معمولی | Record Class | Record Struct |
| :--- | :--- | :--- | :--- | :--- |
| **نوع حافظه** | Reference Type (Heap) | Value Type (Stack/Inline) | Reference Type (Heap) | Value Type (Stack/Inline) |
| **برابری پیش‌فرض (`==`)** | برابری مرجع (Reference) | برابری مقدار (Value) | **برابری مقدار (Value)** | **برابری مقدار (Value)** |
| **پیاده‌سازی `IEquatable<T>`** | ندارد (مگر دستی پیاده‌سازی شود) | ندارد (مگر دستی پیاده‌سازی شود) | **توسط کامپایلر تولید می‌شود** | **توسط کامپایلر تولید می‌شود** |
| **تولید `GetHashCode`** | پیش‌فرض بر اساس Reference | بر اساس Reflection (کند) | **بهینه و بر اساس مقادیر** | **بهینه و بر اساس مقادیر** |
| **تغییرپذیری (Mutability)** | معمولاً Mutable | می‌تواند Mutable باشد | **معمولاً Immutable (غیرقابل تغییر)** | **معمولاً Immutable (غیرقابل تغییر)** |
| **متد `PrintMembers` / `ToString`** | نام کلاس را برمی‌گرداند | نام Struct را برمی‌گرداند | **تمام مقادیر Propertyها را چاپ می‌کند** | **تمام مقادیر Propertyها را چاپ می‌کند** |
| **کاربرد اصلی** | مدل‌سازی رفتار و هویت (Entities) | ساختارهای کوچک داده‌ای | مدل‌سازی داده‌ها و DTOها (Value Objects) | ساختارهای داده‌ای کوچک و تغییرناپذیر |

### نتیجه‌گیری
استفاده از `record` و `record struct` به شما این امکان را می‌دهد که بدون درگیر شدن با پیاده‌سازی‌های خسته‌کننده و مستعد خطای `Equals` و `GetHashCode`، کلاس‌ها و ساختارهایی بسازید که بر اساس **مقدار داده‌هایشان** مقایسه می‌شوند. این ویژگی، نوشتن کدهای تمیزتر، قابل تست‌تر و ایمن‌تر (به ویژه در برنامه‌نویسی Functional و Domain-Driven Design) را به شدت تسهیل می‌کند.
