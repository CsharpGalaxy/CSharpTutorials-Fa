<a name="1-عبارات-لامبدا-lambda-expression-چیست"></a>
## 1. عبارات لامبدا (Lambda Expression) چیست؟
به زبان ساده، **Lambda Expression** یک روش میان‌بر و زیبا برای نوشتن متدهای کوتاه و بی‌نام (Anonymous) در #C است. 
اگر بخواهید یک تکه کد را بنویسید که فقط یک یا دو خط کار انجام می‌دهد و نمی‌خواهید برای آن یک متد کامل با نام و بدنه تعریف کنید، از لامبدا استفاده می‌کنید.

علامت مشخصه لامبدا، عملگر `=>` (خوانده می‌شود: *goes to*) است.
💡 **مثال ساده:**
```csharp
// یک متد معمولی که مربع یک عدد را برمی‌گرداند
int Square(int x) { return x * x; }

// معادل آن با Lambda Expression
x => x * x
```

---

<a name="2-تکامل-رابطه-lambda-با-delegate-و-anonymous-method"></a>
## 2. تکامل: رابطه Lambda با Delegate و Anonymous Method
برای درک لامبدا، باید تاریخچه آن را ببینید. در نسخه‌های قدیمی #C برای پاس دادن یک "رفتار" یا "تابع" به عنوان آرگومان، از **Delegate** استفاده می‌شد.

**مرحله ۱: استفاده از متد نام‌دار (Named Method)**
```csharp
Func<int, int> square = Square; // ارجاع به متد
int Square(int x) { return x * x; }
```

**مرحله ۲: متدهای بی‌نام (Anonymous Method) - معرفی شده در C# 2.0**
```csharp
Func<int, int> square = delegate(int x) { return x * x; };
```
*مشکل:* نوشتن کلمه `delegate` و مشخص کردن نوع پارامترها خسته‌کننده بود.

**مرحله ۳: عبارات لامبدا (Lambda Expression) - معرفی شده در C# 3.0**
```csharp
Func<int, int> square = x => x * x;
```
🎯 **نتیجه:** لامبدا در واقع **نسخه تکامل‌یافته و خلاصه‌شده** همان Anonymous Method است که کار با Delegateها را به شدت ساده کرد.

<a name="3-ساختار-کلی-lambda-expression"></a>
## 3. ساختار کلی Lambda Expression
ساختار لامبدا همیشه از دو بخش اصلی تشکیل شده است که با `=>` از هم جدا می‌شوند:

```text
(پارامترهای ورودی) => (بدنه یا عبارت)
```

بدنه لامبدا می‌تواند دو حالت داشته باشد:
1. **Expression Lambda (تک خطی):** فقط یک عبارت دارد و مقدار آن به صورت خودکار `return` می‌شود.
   `x => x * x`
2. **Statement Lambda (چند خطی):** داخل بلوک `{}` قرار می‌گیرد و باید صریحاً از `return` استفاده کنید.
   `x => { Console.WriteLine(x); return x * x; }`

<a name="4-پارامترهای-lambda-و-type-inference"></a>
## 4. پارامترهای Lambda و Type Inference
شما می‌توانید لامبدا را با تعداد پارامترهای مختلف بنویسید:

* **بدون پارامتر:** `() => Console.WriteLine("Hello")`
* **یک پارامتر:** `x => x * 2` (نیازی به پرانتز نیست)
* **چند پارامتر:** `(x, y) => x + y` (الزاماً داخل پرانتز)

### 🧠 Type Inference (استنتاج نوع)
یکی از جادوهای #C این است که شما **نیازی ندارید نوع پارامترها را بنویسید**. کامپایلر با نگاه کردن به Delegate مقصد (مثلاً `Func<string, int>`)، حدس می‌زند که `x` از نوع `string` است.
```csharp
Func<string, int> getLength = text => text.Length; 
// کامپایلر خودش می‌فهمد text از نوع string است
```

<a name="5-حذف-پارامترهای-غیرضروری-با-_-discards"></a>
## 5. حذف پارامترهای غیرضروری با `_` (Discards)
گاهی اوقات Delegate شما چند پارامتر می‌طلبد، اما شما در بدنه لامبدا به همه آن‌ها نیاز ندارید. در #C (به ویژه از نسخه 12 به بعد) می‌توانید از `_` برای نادیده گرفتن پارامترها استفاده کنید:

```csharp
// در رویدادها (Events) که sender و e را نیاز نداریم
button.Click += (_, _) => Console.WriteLine("Clicked!");

// در LINQ وقتی ایندکس را نمی‌خواهیم
var names = users.Select((user, _) => user.Name);
```
⚠️ **نکته:** استفاده از `_` به کامپایلر و برنامه‌نویسان دیگر می‌گوید: *"من این متغیر را دریافت می‌کنم، اما قصد استفاده از آن را ندارم."*

---

<a name="6-پارامترهای-اختیاری-و-نوع-بازگشتی-در-lambda"></a>
## 6. پارامترهای اختیاری و نوع بازگشتی در Lambda

### پارامترهای اختیاری (Optional Parameters)
خودِ سینتکس لامبدا به تنهایی از پارامترهای اختیاری (مثل `int x = 5`) پشتیبانی **نمی‌کند**. اما اگر لامبدا را به یک Delegate اختصاص دهید که پارامتر اختیاری دارد، کامپایلر آن را می‌پذیرد:
```csharp
public delegate void MyDel(int x, int y = 10);
MyDel del = (x, y) => Console.WriteLine(x + y); // مجاز است
```

### مشخص کردن نوع بازگشتی
در Expression Lambda (تک خطی)، نوع بازگشتی **به صورت خودکار** از روی خروجی عبارت تشخیص داده می‌شود. اما اگر از Statement Lambda (چند خطی) استفاده کنید، کامپایلر نیاز دارد مسیرهای بازگشت را ببیند:
```csharp
// نوع بازگشتی خودکار int تشخیص داده می‌شود
Func<int, int> calc = x => x * 2; 

// در حالت چند خطی، باید صریحاً return کنید
Func<int, int> calc2 = x => {
    int result = x * 2;
    return result; // کامپایلر از اینجا نوع int را می‌فهمد
};
```

<a name="7-مفاهیم-capture-و-closure-بسیار-مهم"></a>
## 7. مفاهیم Capture و Closure (بسیار مهم 🚨)
این بخش مرز بین یک برنامه‌نویس معمولی و یک برنامه‌نویس حرفه‌ای #C است.

### Lambda بدون Capture
اگر لامبدا فقط از پارامترهای ورودی خودش و متغیرهای Static/Global استفاده کند، به آن **بدون Capture** می‌گویند.
```csharp
Func<int, int> square = x => x * x; // هیچ متغیر خارجی را شکار نکرده
```

### Lambda با Capture (شکار متغیر)
اگر لامبدا از یک متغیر محلی (Local Variable) که در scope بیرونی تعریف شده استفاده کند، آن متغیر را **Capture** (شکار) می‌کند.
```csharp
int factor = 5;
Func<int, int> multiply = x => x * factor; // متغیر factor شکار شد!
```

### 🎒 Closure (بسته بسته‌بندی شده) چیست؟
وقتی متد بیرونی تمام می‌شود، متغیرهای محلی آن معمولاً از حافظه پاک می‌شوند. اما اگر یک لامبدا آن‌ها را Capture کرده باشد چه؟
اینجا **Closure** وارد عمل می‌شود. کامپایلر #C به صورت مخفیانه یک **کلاس** می‌سازد، متغیر شکار شده را به عنوان **فیلد** در آن کلاس قرار می‌دهد و لامبدا را به عنوان یک **متد** در همان کلاس تعریف می‌کند.
به این کار Closure می‌گویند: *"لامبدا، متغیرهای محیط اطرافش را در یک کوله‌پشتی (Closure) با خودش حمل می‌کند تا هر زمان که صدا زده شد، به آن‌ها دسترسی داشته باشد."*

---

<a name="8-lambda-در-قالب-delegate"></a>
## 8. Lambda در قالب Delegate
رایج‌ترین استفاده از لامبدا، تبدیل آن به Delegate است. در #C دو Delegate بسیار پرکاربرد برای این کار وجود دارد:
1. **`Action<T>`:** برای لامبدایی که چیزی برنمی‌گرداند (مثل `void`).
2. **`Func<T, TResult>`:** برای لامبدایی که مقداری را برمی‌گرداند.

```csharp
Action<string> sayHi = name => Console.WriteLine($"Hi {name}");
Func<int, int, int> add = (a, b) => a + b;
```

<a name="9-درخت-عبارت-expression-tree-چیست"></a>
## 9. درخت عبارت (Expression Tree) چیست؟
تا الان لامبداها را به عنوان **کد قابل اجرا** می‌دیدیم. اما گاهی ما نمی‌خواهیم کد اجرا شود؛ بلکه می‌خواهیم **ساختار کد** را به عنوان **داده (Data)** بررسی کنیم!
به این ساختار داده‌ای، **Expression Tree** می‌گویند.

در Expression Tree، لامبدا به یک درخت از اشیاء (AST - Abstract Syntax Tree) تبدیل می‌شود. شما می‌توانید این درخت را در حافظه بگردید، تحلیل کنید و حتی به زبان دیگری (مثل SQL) ترجمه کنید.

```csharp
using System.Linq.Expressions;

// توجه به کلمه Expression در ابتدای تعریف
Expression<Func<int, bool>> isEven = x => x % 2 == 0;

// ما می‌توانیم این درخت را بررسی کنیم!
Console.WriteLine(isEven.Body); // چاپ می‌کند: (x % 2) == 0
```
🎯 **کاربرد اصلی:** کتابخانه **Entity Framework Core** از Expression Tree استفاده می‌کند تا کد #C شما را بگیرد و آن را به کوئری **SQL** ترجمه کند.

<a name="10-تفاوت-delegate-و-expression-tree"></a>
## 10. تفاوت Delegate و Expression Tree

| ویژگی | Delegate (Func / Action) | Expression Tree |
| :--- | :--- | :--- |
| **ماهیت** | کد قابل اجرا (Compiled Code) | ساختار داده‌ای (Data Structure) |
| **سرعت اجرا** | بسیار سریع (مستقیم اجرا می‌شود) | کند (باید اول Compile شود) |
| **قابلیت ترجمه** | خیر (فقط در حافظه رم اجرا می‌شود) | بله (قابل تبدیل به SQL، XML و...) |
| **نحوه تعریف** | `Func<int, bool> del = ...` | `Expression<Func<int, bool>> exp = ...` |
| **کاربرد اصلی** | LINQ to Objects (کار با لیست‌ها) | LINQ to Entities (کار با دیتابیس) |

<a name="11-lambda-به-عنوان-syntax-sugar-و-نقش-compiler"></a>
## 11. Lambda به عنوان Syntax Sugar و نقش Compiler
عبارات لامبدا در واقع **Syntax Sugar** (شیرین‌کننده سینتکس) هستند. یعنی زبان #C این قابلیت را ندارد، بلکه این **کامپایلر (Roslyn)** است که کد زیبا و کوتاه شما را می‌گیرد و آن را به کدهای پیچیده و طولانی #C تبدیل می‌کند.

**نقش کامپایلر:**
1. اگر لامبدا **بدون Capture** باشد، کامپایلر آن را به یک **متد Static مخفی** در کلاس شما تبدیل می‌کند.
2. اگر لامبدا **با Capture** باشد، کامپایلر یک **کلاس مخفی (Display Class)** می‌سازد، متغیرها را در آن قرار می‌دهد و لامبدا را به متد آن کلاس تبدیل می‌کند.
3. اگر لامبدا از نوع **Expression Tree** باشد، کامپایلر کدی تولید می‌کند که اشیاء `Expression.Call` و... را برای ساخت درخت عبارت در زمان اجرا (Runtime) ایجاد کند.

<a name="12-تولید-il-و-سه-حالت-اصلی-lambda"></a>
## 12. تولید IL و سه حالت اصلی Lambda
اگر کد #C را کامپایل کنید و به زبان ماشین (IL - Intermediate Language) نگاه کنید (با ابزارهایی مثل ILSpy یا SharpLab)، متوجه می‌شوید که لامبداها در نهایت به یکی از این **سه حالت اصلی** تبدیل می‌شوند:

### حالت اول: Delegate ساده (بدون Closure)
کامپایلر یک متد خصوصی (Private) در همان کلاس شما می‌سازد و Delegate به آن متد اشاره می‌کند.
* **IL تولیدی:** `ldftn` (بارگذاری آدرس متد) و `newobj` (ساخت Delegate).

### حالت دوم: Closure (همراه با Capture)
کامپایلر یک کلاس جدید (مثلاً `<>c__DisplayClass1_0`) می‌سازد. متغیرهای شکار شده فیلدهای این کلاس می‌شوند و لامبدا به متد این کلاس تبدیل می‌گردد.
* **IL تولیدی:** `newobj` (ساخت کلاس مخفی)، `stfld` (ذخیره متغیر در فیلد)، و `ldftn` (اشاره به متد کلاس مخفی).

### حالت سوم: Expression Tree
کامپایلر کدی تولید می‌کند که در زمان اجرا، با استفاده از کلاس‌های `System.Linq.Expressions`، درخت عبارت را در حافظه (Heap) می‌سازد.
* **IL تولیدی:** فراخوانی متدهای `Expression.Lambda`، `Expression.Parameter` و... برای ساخت داینامیک درخت.
