# مقایسه جامع Tuple و Anonymous Type در #C

در زبان #C، زمانی که نیاز به گروه‌بندی موقت چند داده در یک آبجکت داریم، بدون اینکه بخواهیم یک کلاس اختصاصی (Class) برای آن تعریف کنیم، دو گزینه اصلی پیش روی ماست: **Tuple** (به‌طور دقیق‌تر `ValueTuple` که در C# 7.0 معرفی شد) و **Anonymous Type** (که از C# 3.0 در دسترس است). 

اگرچه هر دو برای ذخیره‌سازی موقت داده‌ها استفاده می‌شوند، اما از نظر معماری، عملکرد و کاربرد تفاوت‌های بنیادین با هم دارند. در این مقاله به بررسی دقیق و موشکافانه این دو مفهوم می‌پردازیم.

> **نکته مهم:** در این مقاله، منظور از **Tuple**، همان `System.ValueTuple` (معرفی شده در C# 7.0) است. کلاس قدیمی `System.Tuple` (مربوط به C# 4.0) به دلیل مشکلات عملکردی (Reference Type بودن)، امروزه منسوخ شده و جای خود را به `ValueTuple` داده است.

## بررسی تفاوت‌ها بر اساس معیارهای کلیدی

### 1. Type و Class / Struct
* **Tuple:** یک **Struct** جنریک (`System.ValueTuple<T1, T2, ...>`) است.
* **Anonymous Type:** یک **Class** تولید شده توسط کامپایلر (Compiler-generated) است که نامی شبیه به `<>f__AnonymousType0` دارد.

### 2. Value Type / Reference Type
* **Tuple:** یک **Value Type** است. در Stack (یا به‌صورت اینلاین در آبجکت‌های دیگر) ذخیره می‌شود و سربار Garbage Collection (GC) ندارد.
* **Anonymous Type:** یک **Reference Type** است. در Heap ذخیره می‌شود و باعث افزایش فشار روی Garbage Collector می‌گردد.

### 3. Mutability (تغذیرپذیری)
* **Tuple:** **Mutable** است. فیلدهای آن (`Item1`, `Item2` و...) عمومی هستند و می‌توانید مقدار آن‌ها را پس از ایجاد تغییر دهید.
* **Anonymous Type:** **Immutable** است. پراپرتی‌های آن فقط خواندنی (Read-only) هستند و پس از مقداردهی اولیه در Constructor، قابل تغییر نیستند.

### 4. Member Names (نام‌گذاری اعضا)
* **Tuple:** به‌صورت پیش‌فرض نام اعضا `Item1`, `Item2` است. اما در C# 7.0+ می‌توانید برای آن‌ها نام سفارشی (Custom Names) تعیین کنید. کامپایلر این نام‌ها را در زمان اجرا حفظ نمی‌کند، بلکه از طریق Attribute‌ها در زمان کامپایل مدیریت می‌شوند.
* **Anonymous Type:** نام پراپرتی‌ها مستقیماً از روی نام متغیرها یا پراپرتی‌هایی که در زمان مقداردهی استفاده می‌کنید، استخراج می‌شود و کامپایلر دقیقاً همان‌ها را به‌عنوان پراپرتی‌های کلاس تولید می‌کند.

### 5. Deconstruction (تجزیه)
* **Tuple:** به‌صورت_NATIVE_ از Deconstruction پشتیبانی می‌کند. می‌توانید مقادیر آن را به‌راحتی به متغیرهای جداگانه تجزیه کنید: `var (x, y) = myTuple;`
* **Anonymous Type:** از Deconstruction پشتیبانی **نمی‌کند**.

### 6. LINQ
* **Tuple:** در LINQ قابل استفاده است، اما سینتکس آن برای `Select` کمی طولانی‌تر است.
* **Anonymous Type:** پادشاه LINQ to Objects است! سینتکس `select new { ... }` برای شکل‌دهی (Shape) دادن به داده‌ها در LINQ بی‌نظیر و بسیار خواناست.

### 7. Expression Tree
* **Tuple:** می‌تواند در Expression Treeها استفاده شود.
* **Anonymous Type:** **نمی‌تواند** در Expression Treeها (مانند `Expression<Func<T, TResult>>`) به‌عنوان نوع خروجی استفاده شود، زیرا کامپایلر نمی‌تواند Expression Tree را برای یک نوع بی‌نام تولید کند. *(نکته: این موضوع با قابلیت Translation در EF Core تفاوت دارد؛ در EF Core شما `new {}` را در `Select` می‌نویسید و EF Core آن را به SQL ترجمه می‌کند، اما نمی‌توانید یک Expression Tree مستقل با Anonymous Type بسازید).*

### 8. Return Type (نوع بازگشتی متد)
* **Tuple:** می‌تواند به‌عنوان نوع بازگشتی یک متد (حتو Public) استفاده شود.
* **Anonymous Type:** **نمی‌تواند** به‌عنوان نوع بازگشتی متد استفاده شود (مگر اینکه آن را به `object` یا `dynamic` کست کنید که باعث از بین رفتن Type Safety و IntelliSense می‌شود).

### 9. Accessibility و Scope (دامنه دسترسی)
* **Tuple:** محدودیت Scope ندارد. می‌تواند از یک متد به متد دیگر، یا حتی بین Assemblyها پاس داده شود.
* **Anonymous Type:** Scope آن **فقط محدود به متدی** است که در آن تعریف شده است. کامپایلر این کلاس‌ها را به‌صورت `internal` تولید می‌کند.

### 10. Performance (عملکرد)
* **Tuple:** به دلیل Value Type بودن، تخصیص حافظه آن روی Stack است و **بسیار سریع‌تر** و بهینه‌تر می‌باشد.
* **Anonymous Type:** به دلیل Reference Type بودن، نیاز به تخصیص روی Heap و عملیات GC دارد که در حلقه‌های بزرگ (Loops) باعث افت عملکرد می‌شود.

### 11. Equality (برابری)
* **Tuple:** اپراتور `==` و متد `Equals()` را بر اساس **مقدار (Value-based)** پیاده‌سازی کرده است.
* **Anonymous Type:** متد `Equals()` و `GetHashCode()` را بر اساس مقدار پیاده‌سازی کرده است، اما **اپراتور `==` را پیاده‌سازی نکرده** و `==` در آن بر اساس مرجع (Reference-based) کار می‌کند.

### 12. API Usage (استفاده در APIها)
* **Tuple:** برای بازگرداندن چندین مقدار از یک متد (مثل الگوی `TryParse`) یا استفاده در APIهای عمومی عالی است.
* **Anonymous Type:** فقط برای استفاده‌های **داخلی و موقت** (Internal/Local) در همان متد طراحی شده است.

### 13. Serialization (سریال‌سازی)
* **Tuple:** به‌راحتی توسط Serializerهای مدرن (مثل `System.Text.Json` یا `Newtonsoft`) پشتیبانی می‌شود (البته برای نام‌گذاری فیلدها در JSON نیاز به تنظیمات یا Attribute دارد).
* **Anonymous Type:** سریال‌سازی آن‌ها **بسیار دشوار** است. به دلیل Immutable بودن و مخفی بودن نوع واقعی، بسیاری از Serializerها در تبدیل آن‌ها به JSON/XML دچار مشکل می‌شوند.

## جدول مقایسه سریع

| معیار | Tuple (`ValueTuple`) | Anonymous Type |
| :--- | :--- | :--- |
| **نوع پایه (Type)** | `System.ValueTuple` (Generic Struct) | Compiler-generated Class |
| **محل ذخیره‌سازی** | Value Type (Stack) | Reference Type (Heap) |
| **تغذیرپذیری (Mutability)** | Mutable (قابل تغییر) | Immutable (فقط خواندنی) |
| **نام‌گذاری اعضا** | `Item1`, `Item2` یا نام‌های سفارشی | بر اساس نام متغیرهای انتسابی |
| **Deconstruction** | ✅ پشتیبانی می‌شود | ❌ پشتیبانی نمی‌شود |
| **LINQ Projections** | قابل استفاده (اما سینتکس ضعیف‌تر) | ✅ عالی و استاندارد (`select new {}`) |
| **Expression Tree** | ✅ پشتیبانی می‌شود | ❌ پشتیبانی نمی‌شود |
| **Return Type متد** | ✅ مجاز است | ❌ مجاز نیست (مگر با `object`/`dynamic`) |
| **دامنه (Scope)** | نامحدود (Global/Assembly) | فقط محدود به همان متد (Method-level) |
| **عملکرد (Performance)** | بسیار بالا (بدون سربار GC) | پایین‌تر (دارای سربار Heap و GC) |
| **اپراتور `==`** | ✅ مقایسه بر اساس مقدار | ❌ مقایسه بر اساس مرجع (Reference) |
| **متد `Equals()`** | ✅ مقایسه بر اساس مقدار | ✅ مقایسه بر اساس مقدار |
| **Serialization** | ✅ پشتیبانی می‌شود | ❌ بسیار دشوار / نیازمند Reflection |
| **کاربرد اصلی** | بازگشت چند مقدار، عبور از مرز متدها | شکل‌دهی موقت داده‌ها در LINQ و متدها |

## سناریوها: کدام را انتخاب کنیم؟

در ادامه چند سناریوی واقعی را بررسی می‌کنیم تا بهترین انتخاب را مشخص کنیم:

### سناریو ۱: بازگرداندن چند مقدار از یک متد
**کد:**
```csharp
public (int Id, string Name, bool IsActive) GetUserBriefInfo(int userId)
{
    // ...
    return (101, "Ali", true);
}
```
🏆 **انتخاب بهتر:** **Tuple**
**دلیل:** شما نیاز دارید داده‌ها را از مرز متد عبور دهید. Anonymous Type اجازه Return Type شدن را ندارد و استفاده از `object` باعث از بین رفتن Type Safety می‌شود.

### سناریو ۲: شکل‌دهی (Shape) داده‌ها در LINQ
**کد:**
```csharp
var userSummaries = users.Select(u => new 
{
    u.Id,
    FullName = u.FirstName + " " + u.LastName,
    u.Email
}).ToList();
```
🏆 **انتخاب بهتر:** **Anonymous Type**
**دلیل:** سینتکس Anonymous Type در LINQ بسیار تمیزتر است. چون فقط در همان متد و به‌صورت موقت به داده‌ها شکل می‌دهید، نیازی به عبور از مرز متد ندارید.

### سناریو ۳: پردازش در حلقه‌های بزرگ (High-Performance)
**کد:**
```csharp
// پردازش میلیون‌ها رکورد
for(int i=0; i<1000000; i++) {
    var tempData = (i, i * 2); // Tuple
    // var tempData = new { a = i, b = i * 2 }; // Anonymous
}
```
🏆 **انتخاب بهتر:** **Tuple**
**دلیل:** استفاده از Anonymous Type در این حلقه باعث تخصیص یک میلیون آبجکت روی Heap و فشار شدید به Garbage Collector می‌شود. Tuple روی Stack ساخته شده و هیچ سرباری ندارد.

### سناریو ۴: کار با Entity Framework Core (ترجمه به SQL)
**کد:**
```csharp
var result = await context.Products
    .Select(p => new { p.Name, p.Price })
    .ToListAsync();
```
🏆 **انتخاب بهتر:** **Anonymous Type**
**دلیل:** اگرچه EF Core از `ValueTuple` نیز پشتیبانی می‌کند، اما Anonymous Typeها سال‌هاست که استاندارد طلایی برای Projection در LINQ to Entities هستند و EF Core به‌راحتی آن‌ها را به ستون‌های SQL ترجمه می‌کند.

### سناریو ۵: نیاز به سریال‌سازی (مثلاً ارسال به Redis یا Kafka)
🏆 **انتخاب بهتر:** **Tuple** (یا ترجیحاً یک Record/Class)
**دلیل:** سریالایزرها با پراپرتی‌های فقط خواندنی و تایپ‌های مخفی Anonymous Type مشکل دارند. `ValueTuple` یا `Record`ها گزینه‌های استانداردتری برای این کار هستند.

## جمع‌بندی و دیدگاه مستندات رسمی Microsoft

بر اساس **مستندات رسمی Microsoft**، رویکرد مایکروسافت به این صورت است:

> *"استفاده از `ValueTuple` برای بسیاری از سناریوهای سبک، موقت و محلی ترجیح داده می‌شود، زیرا به‌عنوان یک Value Type، سربار حافظه ندارد و از قابلیت‌های مدرنی مانند Deconstruction پشتیبانی می‌کند. با این حال، `Anonymous Type` همچنان در سناریوهایی که نیاز به یک Reference Type دارید، یا در Projectionهای کلاسیک LINQ و زمانی که نمی‌خواهید نام فیلدها را به‌صورت صریح در امضای متد تعریف کنید، مناسب‌تر و خواناتر است."*

**قانون طلایی:**
* اگر داده‌ها **فقط در همان متد** هستند و برای **LINQ** استفاده می‌شوند 👈 **Anonymous Type**
* اگر داده‌ها باید **از متدی به متد دیگر** بروند، **Performance** مهم است، یا نیاز به **Deconstruction** دارید 👈 **Tuple**
* *(نکته حرفه‌ای: اگر داده‌های شما قرار است در یک API عمومی قرار بگیرند یا عمر طولانی‌تری دارند، به جای هر دوی این‌ها، از `Record` یا `Class`های اختصاصی استفاده کنید).*
