## مقدمه
وقتی برای اولین بار با LINQ یا ساختارهای داده‌ای موقت در C# کار می‌کنید، احتمالاً با `new { ... }` مواجه شده‌اید. این یعنی شما در حال ساخت یک **Anonymous Type** هستید. اما وقتی می‌خواهید این داده را به یک متد دیگر بفرستید یا آن را در یک کلاس ذخیره کنید، با دیواری از خطاهای کامپایلر روبرو می‌شوید! در این مقاله دقیقاً بررسی می‌کنیم که چرا این اتفاق می‌افتد و چگونه باید آن را مدیریت کنیم.

---

## ۱. Scope (حوزه دسترسی) در C# چیست؟
**Scope** یا حوزه دسترسی، مشخص می‌کند که یک متغیر یا یک Type در کجای کد شما «قابل مشاهده» (Visible) و «قابل استفاده» (Accessible) است. 
در C# چندین نوع Scope داریم:
1. **Block Scope:** متغیراتی که داخل `{ }` تعریف می‌شوند (مثل داخل حلقه‌ها یا `if`).
2. **Method/Local Scope:** متغیراتی که داخل یک متد تعریف می‌شوند و فقط تا پایان همان متد زنده هستند.
3. **Class Scope:** فیلدها و پراپرتی‌های یک کلاس.
4. **Namespace Scope:** کلاس‌ها و تایپ‌هایی که در سطح Namespace تعریف می‌شوند.

---

## ۲. Anonymous Type چیست و در چه Scopeای قابل استفاده است؟
**Anonymous Type** یک کلاس بدون نام است که توسط کامپایلر در زمان کامپایل (Compile-time) تولید می‌شود. شما فقط ساختار آن (Propertyها) را تعریف می‌کنید و کامپایلر بقیه کارها را انجام می‌دهد.

**قانون طلایی:** Anonymous Typeها **فقط و فقط در Local Scope (Scope محلی متدها)** قابل استفاده هستند. 
شما **نمی‌توانید** یک Anonymous Type را به عنوان فیلد یک کلاس، پراپرتی، یا پارامتر صریح یک متد تعریف کنید.

---

## ۳. چرا Type Name آن در Source Code قابل دسترسی نیست؟
وقتی شما می‌نویسید:
```csharp
var user = new { Name = "Ali", Age = 30 };
```
کامپایلر C# در پشت صحنه یک کلاس با نامی شبیه به این تولید می‌کند:
`<>f__AnonymousType0<string, int>`

**دلیل عدم دسترسی:**
1. **نام نامعتبر:** نامی که کامپایلر تولید می‌کند شامل کاراکترهای `<` و `>` است که در سینتکس C# برای تعریف متغیر یا کلاس غیرقانونی است.
2. **طراحی زبان:** طراحان C# (از جمله Anders Hejlsberg) عمداً نام این تایپ‌ها را مخفی نگه داشتند تا برنامه‌نویس را مجبور کنند از آن‌ها فقط برای مقاصد موقت و محلی استفاده کند و آن‌ها را به عنوان بخشی از Contract (قرارداد) عمومی برنامه در نیاورد.

---

## ۴. رابطه Scope با کلمه کلیدی var
از آنجایی که ما نام تایپ را نمی‌دانیم، **مجبوریم** برای تعریف متغیرهای Anonymous Type از `var` استفاده کنیم.
```csharp
// صحیح
var person = new { Name = "Sara" }; 

// خطای کامپایلر: نمی‌توانید نام تایپ را بنویسید چون وجود خارجی در سورس کد ندارد
// <>f__AnonymousType0<string> person = new { Name = "Sara" }; 
```
**نکته مهم:** `var` در C# به معنی "Dynamic" یا "تایپ ناشناس در زمان اجرا" **نیست**. `var` یعنی "کامپایلر، تایپ را از روی مقدار سمت راست حدس بزن". بنابراین، `person` در مثال بالا یک متغیر **Strongly Typed** (قویاً تایپ شده) است و Scope آن دقیقاً همان Scope محلی است که در آن تعریف شده.

---

## ۵. دسترسی به Propertyهای Anonymous Type
چون تایپ در زمان کامپایل مشخص می‌شود، شما دسترسی کامل، ایمن (Type-safe) و همراه با IntelliSense به پراپرتی‌ها دارید:

```csharp
var product = new { Id = 101, Title = "Laptop", Price = 1200.50 };

Console.WriteLine(product.Title); // دسترسی مستقیم و ایمن
// product.Title = "PC"; // خطا! پراپرتی‌های Anonymous Type فقط Read-Only هستند.
```

## ۶. استفاده در همان Method، LINQ و Collectionها

### الف) استفاده در همان Method
بهترین و استانداردترین حالت استفاده، محدود کردن آن به همان متدی است که در آن ساخته شده:
```csharp
public void CalculateDiscount()
{
    var item = new { Name = "Book", Price = 50 };
    var discountedItem = new { item.Name, FinalPrice = item.Price * 0.9 };
    
    Console.WriteLine($"{discountedItem.Name} costs {discountedItem.FinalPrice}");
}
```

### ب) استفاده در LINQ
Anonymous Typeها ستاره‌های درخشان LINQ هستند. وقتی می‌خواهید فقط بخش خاصی از داده‌ها را Select کنید:
```csharp
var users = new List<User> { /* ... */ };

var userNames = users.Select(u => new 
{ 
    FullName = u.FirstName + " " + u.LastName, 
    u.Email 
}).ToList();
```

### ج) استفاده در Collectionها
شما نمی‌توانید `List<AnonymousType>` بسازید، اما می‌توانید از **Type Inference** در آرایه‌ها استفاده کنید (به شرطی که همه المان‌ها ساختار و ترتیب یکسانی داشته باشند):
```csharp
// صحیح: کامپایلر تایپ آرایه را از روی المان اول حدس می‌زند
var scores = new[] 
{
    new { Student = "Ali", Score = 18 },
    new { Student = "Reza", Score = 20 }
};

// غلط: ساختارها باید دقیقاً یکسان باشند
var mixed = new[] 
{
    new { A = 1 },
    new { B = 2 } // خطای کامپایلر!
};
```

## ۷. چالش عبور دادن Anonymous Type به متدها (object و dynamic)
حالا به مشکل اصلی می‌رسیم: چگونه یک Anonymous Type را به یک متد دیگر پاس دهیم یا از یک متد برگردانیم؟

### روش اول: استفاده از `object` (توصیه نمی‌شود)
```csharp
public object GetPerson()
{
    return new { Name = "Ali", Age = 30 };
}

// استفاده:
var obj = GetPerson();
// obj.Name -> خطا! چون obj از نوع object است و پراپرتی Name را نمی‌شناسد.
```
*مشکل:* برای دسترسی به پراپرتی‌ها باید از **Reflection** استفاده کنید که بسیار کند و پرخطا است.

### روش دوم: استفاده از `dynamic` (کار می‌کند اما خطرناک است)
```csharp
public dynamic GetPerson()
{
    return new { Name = "Ali", Age = 30 };
}

// استفاده:
dynamic obj = GetPerson();
Console.WriteLine(obj.Name); // کار می‌کند!
```
*مشکل:* بررسی تایپ به زمان اجرا (Runtime) موکول می‌شود. اگر `obj.Nme` را اشتباه تایپ کنید، کامپایلر خطا نمی‌گیرد اما برنامه در Runtime کرش می‌کند. همچنین Performance کاهش می‌یابد.

### روش سوم: استفاده از Generics (بهترین راه برای متدها)
اگر مجبورید Anonymous Type را به متد پاس دهید، از Generic استفاده کنید تا تایپ Safety حفظ شود:
```csharp
public void PrintInfo<T>(T data)
{
    // در اینجا نمی‌توانید مستقیماً به پراپرتی‌ها دسترسی داشته باشید 
    // مگر اینکه از dynamic استفاده کنید یا فقط ToString را چاپ کنید.
    Console.WriteLine(data.ToString()); 
}
```
*(نکته: اگر نیاز به دسترسی به پراپرتی‌ها در متد Generic دارید، یعنی نباید از Anonymous Type استفاده کنید و باید یک Class/Record بسازید).*

## ۸. محدودیت‌های دسترسی Type
برای مرور، محدودیت‌های Anonymous Type عبارتند از:
1. فقط می‌تواند به عنوان **متغیر محلی (Local Variable)** تعریف شود.
2. نمی‌تواند فیلد، پراپرتی، یا بازگشت (Return Type) یک متد باشد.
3. نمی‌تواند پیاده‌ساز یک Interface باشد.
4. پراپرتی‌های آن **فقط Read-Only** (غیرقابل تغییر) هستند.
5. فقط می‌تواند پراپرتی‌های ساده داشته باشد (نمی‌تواند فیلد، متد، یا Event داشته باشد).

## ۹. مثال‌های صحیح و اشتباه + خطاهای رایج

### ❌ اشتباه ۱: تلاش برای تعریف به عنوان فیلد کلاس
```csharp
public class MyClass
{
    // خطای کامپایلر: Cannot assign anonymous type to an explicitly typed class field
    public var MyProperty = new { Id = 1 }; 
}
```

### ❌ اشتباه ۲: تلاش برای Cast کردن object به Anonymous Type
```csharp
object obj = new { Name = "Ali" };
// خطا: نمی‌توانید به تایپ ناشناس کست کنید چون نامش را نمی‌دانید!
var casted = (var)obj; 
```

### ❌ اشتباه ۳: تغییر مقدار پراپرتی
```csharp
var data = new { Count = 10 };
data.Count = 20; // خطا: پراپرتی‌های Anonymous Type فقط خواندنی هستند.
```

### ✅ مثال صحیح (استفاده استاندارد)
```csharp
public void ProcessData()
{
    var tempData = new { Status = "Success", Code = 200 };
    
    if (tempData.Status == "Success")
    {
        Console.WriteLine($"Processed with code {tempData.Code}");
    }
}
```

## ۱۰. راهکارهای مناسب برای انتقال داده بین بخش‌های برنامه
اگر متوجه شدید که نیاز دارید یک Anonymous Type را از یک متد به متد دیگر، یا از یک کلاس به کلاس دیگر منتقل کنید، **این یک نشانه (Red Flag) است که نباید از Anonymous Type استفاده کنید.** 

**راهکارهای جایگزین و استاندارد:**

1. **استفاده از Tuples (تاپل‌ها - C# 7.0 به بعد):**
   بهترین جایگزین برای انتقال داده‌های ساده و موقت بین متدها.
   ```csharp
   public (string Name, int Age) GetPerson()
   {
       return ("Ali", 30);
   }
   ```

2. **استفاده از Records (C# 9.0 به بعد):**
   اگر داده‌های شما ساختاریافته هستند و نیاز به Value-equality دارید، از `record` استفاده کنید.
   ```csharp
   public record PersonDto(string Name, int Age);
   ```

3. **استفاده از کلاس‌ها یا DTOهای معمولی:**
   برای ساختارهای پیچیده‌تر و انتقال در لایه‌های مختلف برنامه (مثل بین دیتابیس و UI).

## جمع‌بندی
- **Anonymous Type** ابزاری عالی برای ایجاد اشیاء موقت، به‌ویژه در **LINQ** و **Scopeهای محلی** است.
- نام این تایپ‌ها توسط کامپایلر تولید شده و در سورس‌کد قابل دسترسی نیست؛ بنابراین **مجبور** به استفاده از `var` هستیم.
- این تایپ‌ها **Strongly Typed** و **Read-Only** هستند.
- **هرگز** سعی نکنید آن‌ها را به عنوان فیلد کلاس، پارامتر متد، یا Return Type استفاده کنید.
- برای انتقال داده بین متدها و بخش‌های مختلف برنامه، به جای Anonymous Type از **Tuples**، **Records** یا **DTO Classes** استفاده کنید.
