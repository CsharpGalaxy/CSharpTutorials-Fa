## 1. مقدمه: تفاوت Syntax سطح بالا و اجرای واقعی
وقتی ما کدی می‌نویسیم، در حال استفاده از **Syntax سطح بالا (High-Level Syntax)** هستیم. این کدها برای *انسان* نوشته شده‌اند تا خوانا و قابل درک باشند. اما CPU و سیستم‌عامل ما زبان `yield` یا `foreach` را نمی‌فهمند!

**یک مثال ساده:**
```csharp
// Syntax سطح بالا (چیزی که ما می‌نویسیم)
public IEnumerable<int> GetNumbers() {
    yield return 1;
    yield return 2;
}
```
**اجرای واقعی (چیزی که کامپیوتر می‌فهمد):**
کامپیوتر مفهومی به نام "توقف موقت و برگشت به همان نقطه" ندارد. در سطح پایین (IL/Assembly)، ما فقط با پرش‌ها (`goto`)، متغیرها و شرط‌ها (`switch/if`) سر و کار داریم. 
**وظیفه Compiler (کامپایلر)** این است که این "شکر روی کیک" (Syntactic Sugar) را بگیرد و آن را به یک ماشین حالت (State Machine) پیچیده تبدیل کند که CPU بتواند اجرا کند.

## 2. Iterator و حلقه `foreach` چگونه کار می‌کنند؟
قبل از درک State Machine، باید بدانیم `foreach` چطور کار می‌کند. حلقه `foreach` در واقع یک `while` loop است که پشت صحنه از یک **Iterator** (تکرارگر) استفاده می‌کند.

یک Iterator باید سه کار اصلی انجام دهد:
1. شروع کند.
2. مقدار بعدی را بدهد (`Current`).
3. به مرحله بعد برود (`MoveNext`).

وقتی شما `yield return` می‌نویسید، در حال ساختن یک Iterator هستید. اما چون نوشتن کلاس‌های Iterator به صورت دستی بسیار خسته‌کننده است، کامپایلر این کار را برای شما انجام می‌دهد.

## 3. رابطه `yield` و State Machine (جادوی کامپایلر)
**State Machine (ماشین حالت)** چیست؟ 
تصور کنید یک دستگاه خودپرداز (ATM) دارید. این دستگاه در "حالت‌های" مختلفی است:
* حالت ۱: دریافت کارت
* حالت ۲: دریافت پین
* حالت ۳: انتخاب عملیات

کامپایلر C# وقتی به کلمه `yield` می‌رسد، متد شما را به یک **State Machine** تبدیل می‌کند. هر `yield return` در کد شما، تبدیل به یک "حالت" (State) جدید در این ماشین می‌شود. کامپایلر یک متغیر عددی نگه می‌دارد تا بداند الان در کدام حالت است و دفعه بعد که صدا زده شد، دقیقاً از همانجا ادامه دهد.

## 4. کالبدشکافی کلاس داخلی تولیدشده توسط Compiler
وقتی کامپایلر (Roslyn) متدی که دارای `yield` است را می‌بیند، متد اصلی شما را خالی می‌کند و به جای آن یک **کلاس داخلی (Inner Class)** در سطح اسمبلی تولید می‌کند.

**چرا کلاس و نه Struct؟**
چون State Machine باید وضعیت (State) خود را بین فراخوانی‌های مختلف **به خاطر بسپارد**. اگر Struct بود، با هر بار کپی شدن، وضعیت قبلی از بین می‌رفت. پس کامپایلر یک کلاس روی Heap (حافظه پویا) می‌سازد.

نام این کلاس معمولاً چیزی شبیه به این است:
`<GetNumbers>d__0`
این کلاس دو رابط (Interface) مهم را پیاده‌سازی می‌کند:
1. `IEnumerable<T>` (برای شروع حلقه)
2. `IEnumerator<T>` (برای حرکت بین آیتم‌ها)

## 5. بررسی فیلدهای حیاتی: State Field و Current Field
اگر کد دی‌کامپایل شده (مثلاً با ابزار ILSpy) را ببینید، با فیلدهای عجیبی روبرو می‌شوید. مهم‌ترین آن‌ها عبارتند از:

### الف) State Field (`<>1__state`)
این یک متغیر `int` است که قلب تپنده State Machine است.
* **`-1`**: یعنی State Machine هنوز شروع نشده (Start).
* **`-2`**: یعنی کار تمام شده است (Finished).
* **`0, 1, 2, ...`**: نشان‌دهنده شماره خط/مرحله‌ای است که باید اجرا شود.

### ب) Current Field (`<>2__current`)
این فیلد مقداری را نگه می‌دارد که قرار است در هر چرخه به حلقه `foreach` برگردانده شود. وقتی `yield return 5` را می‌نویسید، کامپایلر عدد 5 را درون `Current` می‌ریزد.

### ج) فیلدهای محلی (Local Fields)
اگر در متد خود متغیری مثل `int i = 0;` داشته باشید، کامپایلر آن را به عنوان یک فیلد در همین کلاس داخلی ذخیره می‌کند تا بین فراخوانی‌ها مقدارش حفظ شود.

## 6. موتور محرک: متد `MoveNext()` چیست؟
حلقه `foreach` در هر چرخه، متد `MoveNext()` را از روی State Machine صدا می‌زند. این متد شامل یک غول مرحله آخر به نام `switch` است!

**شکل شماتیک `MoveNext` تولید شده توسط کامپایلر:**
```csharp
private bool MoveNext()
{
    switch (<>1__state)
    {
        case 0: // حالت اول
            goto IL_0001;
        case 1: // حالت دوم
            goto IL_0002;
        case -2: // پایان کار
            return false;
    }

    IL_0001:
    // کدهای مربوط به yield return اول
    <>2__current = 1; // مقدار Current تنظیم می‌شود
    <>1__state = 1;   // State به مرحله بعد می‌رود
    return true;      // به foreach می‌گوید "ادامه بده"

    IL_0002:
    // کدهای مربوط به yield return دوم
    <>2__current = 2;
    <>1__state = -2;  // State به حالت پایان می‌رود
    return true;
}
```
**نکته کلیدی:** حلقه `foreach` تا زمانی که `MoveNext()` مقدار `true` برگرداند، به کار خود ادامه می‌دهد و مقدار `Current` را می‌خواند.

## 7. مباحث پیشرفته: تاثیر State Machine بر حافظه و Async/Await

### 🚨 چالش حافظه (Memory Allocation)
از آنجا که کامپایلر برای هر متد Iterator یک **کلاس** می‌سازد، هر بار که متد را صدا می‌زنید، یک آبجکت جدید روی **Heap** ساخته می‌شود. این موضوع باعث افزایش فشار روی Garbage Collector (GC) می‌شود.
* **راه‌حل پیشرفته:** در نسخه‌های جدیدتر C# و .NET، برای سناریوهای خاص و پرفورمنسی، از `ref struct` و `Span<T>` استفاده می‌شود تا از تخصیص Heap جلوگیری شود (مفاهیمی مثل `IAsyncEnumerable` و `ValueTask`).

### 🔄 ارتباط با `async` و `await`
آیا می‌دانستید `async/await` دقیقاً از **همین تکنیک State Machine** استفاده می‌کند؟
وقتی از `await` استفاده می‌کنید، کامپایلر متد شما را به یک State Machine تبدیل می‌کند. با این تفاوت که:
* در `yield`، State Machine برای تولید لیست (`IEnumerable`) است.
* در `async`، State Machine برای مدیریت Taskها و ادامه کار پس از اتمام یک عملیات ناهمگام (`IAsyncStateMachine`) است.
درک `yield` بهترین سکوی پرتاب برای درک عمیق `async/await` است!
