## ۱. حلقه `foreach` چیست؟
حلقه `foreach` یک ساختار کنترلی در #C است که برای پیمایش (Iterate) روی مجموعه‌ها (Collections) مانند آرایه‌ها، لیست‌ها، دیکشنری‌ها و... استفاده می‌شود.

**تشبیه ساده:**
فرض کنید یک کتاب دارید. حلقه `for` معمولی مثل این است که بگویید: "از صفحه ۱ تا صفحه ۱۰۰، صفحه شماره `i` را بخوان". اما `foreach` مثل این است که بگویید: "هر صفحه‌ای که در کتاب هست را به ترتیب بخوان، بدون اینکه من را درگیر شماره صفحات کنی".

**مثال ساده:**
```csharp
List<string> fruits = new List<string> { "سیب", "موز", "پرتقال" };

foreach (string fruit in fruits)
{
    Console.WriteLine(fruit);
}
```
✨ **مزیت بزرگ:** نیاز نیست نگران `IndexOutOfRangeException` (خطای خارج از محدوده ایندکس) باشید، چون خودش می‌داند کی باید متوقف شود.

## ۲. رابطه `foreach` با `IEnumerable`
وقتی شما روی یک متغیر `foreach` می‌نویسید، کامپایلر #C به نوع داده نگاه نمی‌کند (اینکه لیست است یا آرایه). کامپایلر فقط دنبال یک **قرارداد (Interface)** می‌گردد به نام `IEnumerable`.

رابط `IEnumerable` فقط یک متد دارد:
```csharp
public interface IEnumerable
{
    IEnumerator GetEnumerator();
}
```
**معنی ساده:** `IEnumerable` به کامپایلر می‌گوید: "من یک مجموعه هستم و اگر یک `Enumerator` (شمارشگر) از من بخواهی، من به تو می‌دهم تا بتوانی اعضایم را یکی‌یکی بخوانی."

> 💡 **نکته پیشرفته:** در #C مدرن، رابط `IEnumerable<T>` (نوع جنریک) نیز وجود دارد که برای جلوگیری از Boxing/Unboxing و افزایش پرفورمنس استفاده می‌شود، اما منطق `foreach` برای هر دو یکسان است.

---

## ۳. رابطه `foreach` با `IEnumerator`
وقتی `foreach` متد `GetEnumerator()` را روی مجموعه صدا می‌زند، یک `IEnumerator` دریافت می‌کند. `IEnumerator` در واقع **همان چشم و دستِ حلقه `foreach`** است که روی مجموعه حرکت می‌کند.

این رابط سه عضو اصلی دارد:
```csharp
public interface IEnumerator
{
    object Current { get; }      // عنصر فعلی را برمی‌گرداند
    bool MoveNext();             // به عنصر بعدی می‌رود (اگر وجود داشت true برمی‌گرداند)
    void Reset();                // (قدیمی و کم‌کاربرد) مکان‌نما را به اول برمی‌گرداند
}
```
`foreach` در واقع با این `IEnumerator` کار دارد تا بداند الان روی کدام عنصر است و آیا عنصر بعدی وجود دارد یا خیر.

## ۴. تبدیل `foreach` به کد سطح پایین (پشت صحنه)
این جذاب‌ترین بخش برای برنامه‌نویسان است! وقتی شما کد زیر را می‌نویسید:

```csharp
foreach (var item in collection)
{
    Console.WriteLine(item);
}
```

کامپایلر #C آن را به کد معادل زیر (سطح پایین) تبدیل می‌کند:

```csharp
var enumerator = collection.GetEnumerator();
try
{
    while (enumerator.MoveNext())
    {
        var item = enumerator.Current;
        Console.WriteLine(item);
    }
}
finally
{
    // اگر Enumerator قابلیت Dispose داشته باشد، آن را آزاد می‌کند
    (enumerator as IDisposable)?.Dispose();
}
```
🔥 **نتیجه‌گیری مهم:** حلقه `foreach` در واقع یک حلقه `while` است که درون یک بلوک `try-finally` قرار گرفته تا مدیریت منابع (Resources) به درستی انجام شود.

---

## ۵. ترتیب اجرای `MoveNext` و `Current`
درک ترتیب اجرای این دو متد بسیار حیاتی است:

1. **ابتدا `MoveNext()` صدا زده می‌شود:** این متد مکان‌نما (Cursor) را یک قدم به جلو می‌برد. اگر به انتهای مجموعه رسیده باشد، مقدار `false` و در غیر این صورت `true` برمی‌گرداند.
2. **سپس `Current` خوانده می‌شود:** اگر `MoveNext` مقدار `true` برگردانده باشد، مقدار عنصر فعلی از `Current` خوانده می‌شود.

⚠️ **هشدار:** اگر قبل از اینکه `MoveNext` برای اولین بار صدا زده شود، یا بعد از اینکه `MoveNext` مقدار `false` برگرداند، سعی کنید `Current` را بخوانید، با خطا (Exception) مواجه می‌شوید یا رفتار غیرقابل پیش‌بینی خواهد بود.

---

## ۶. اجرای `Dispose` در `foreach` (مدیریت حافظه)
همانطور که در بخش ۴ دیدید، کامپایلر یک بلوک `finally` ایجاد می‌کند. چرا؟
چون برخی از `Enumerator`ها ممکن است منابع سیستمی (مثل اتصال به دیتابیس، خواندن فایل از هارد، یا شبکه) را در اختیار داشته باشند. این منابع پیاده‌سازی رابط `IDisposable` هستند.

کامپایلر #C به صورت هوشمند بررسی می‌کند که آیا `IEnumerator` رابط `IDisposable` را پیاده‌سازی کرده است یا خیر. اگر بله، در پایان حلقه (چه موفق، چه با خطا، چه با break) متد `Dispose()` را صدا می‌زند تا منابع آزاد شوند.

---

## ۷. رفتار `break` در `foreach`
فرض کنید در حال پیمایش یک لیست ۱۰۰۰ تایی هستید و در آیتم دهم می‌خواهید با `break` از حلقه خارج شوید.

```csharp
foreach (var item in largeCollection)
{
    if (item == target) break;
    // ...
}
```
**چه اتفاقی می‌افتد؟**
وقتی `break` اجرا می‌شود، کنترل از حلقه `while` خارج شده و **مستقیماً وارد بلوک `finally` می‌شود**.
بنابراین، حتی اگر شما حلقه را زودتر از موعد قطع کنید، متد `Dispose` (اگر وجود داشته باشد) **حتماً** صدا زده می‌شود و منابع نشت (Leak) نمی‌کنند. این یکی از شاهکارهای طراحی `foreach` است.

---

## ۸. رفتار `Exception` داخل `foreach`
اگر در بدنه حلقه `foreach` خطایی (Exception) رخ دهد چه می‌شود؟ آیا `Enumerator` در حافظه رها می‌شود؟

```csharp
try
{
    foreach (var item in collection)
    {
        if (item == null) throw new Exception("خطای تستی!");
    }
}
catch (Exception ex)
{
    Console.WriteLine("خطا رخ داد.");
}
```
**پاسخ:** خیر، رها نمی‌شود!
به لطف بلوک `try-finally` که کامپایلر در پشت صحنه می‌سازد (بخش ۴)، وقتی Exception رخ می‌دهد، اجرای برنامه به سمت `catch` می‌رود، اما قبل از آن، بلوک `finally` اجرا شده و `Dispose` فراخوانی می‌شود.
این یعنی `foreach` از نظر مدیریت منابع (Resource Management) کاملاً **ایمن (Safe)** طراحی شده است.
