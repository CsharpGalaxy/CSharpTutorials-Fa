## 1. مفهوم `yield return` چیست؟

بیایید با یک مثال ساده شروع کنیم. فرض کنید می‌خواهید ۵ عدد اول را به کاربر برگردانید.
روش سنتی این است که یک `List` بسازید، اعداد را در آن بریزید و در نهایت لیست را `return` کنید. اما این کار **حافظه (RAM)** را اشغال می‌کند.

**`yield return`** به شما اجازه می‌دهد که آیتم‌ها را **یکی‌یکی** و **در لحظه** تولید کنید و به مصرف‌کننده تحویل دهید، بدون اینکه نیازی به ساخت یک مجموعه میانی (مثل List) باشد.

### 💡 مثال ساده:
```csharp
public IEnumerable<int> GetNumbers()
{
    yield return 1; // عدد 1 را تولید و برگردان
    yield return 2; // عدد 2 را تولید و برگردان
    yield return 3; // عدد 3 را تولید و برگردان
}
```
در اینجا هیچ لیستی در حافظه ساخته نمی‌شود! کامپایلر سی‌شارپ به صورت خودکار کدی را تولید می‌کند که هر بار که شما روی نتیجه حلقه `foreach` بزنید، فقط یک عدد را به شما بدهد.

## 2. مفهوم `yield break` چیست؟

اگر `yield return` وظیفه تولید و ارسال یک آیتم را دارد، **`yield break`** وظیفه **توقف کامل و زودهنگام** فرآیند تولید را بر عهده دارد. دقیقاً مثل کلمه `break` در حلقه‌های `for` یا `while`.

### 💡 مثال:
فرض کنید می‌خواهیم اعداد را تولید کنیم، اما اگر به عدد ۳ رسیدیم، کلاً متوقف شویم.

```csharp
public IEnumerable<int> GenerateWithCondition()
{
    for (int i = 1; i <= 10; i++)
    {
        if (i == 3)
        {
            yield break; // توقف کامل Iterator
        }
        yield return i;
    }
}
```
**خروجی:** فقط اعداد `1` و `2` چاپ خواهند شد. به محض رسیدن به ۳، متد کاملاً بسته می‌شود.

## 3. نحوه نوشتن یک Iterator

برای نوشتن یک متد Iterator، باید چند قانون ساده را رعایت کنید:
1. نوع بازگشتی متد باید یکی از موارد زیر باشد: `IEnumerable`، `IEnumerable<T>`، `IEnumerator` یا `IEnumerator<T>`.
2. در بدنه متد باید حداقل از یک `yield return` یا `yield break` استفاده کنید.

### 💡 مثال کاربردی (فیلتر کردن کاربران):
```csharp
public class User { public string Name { get; set; } public int Age { get; set; } }

public IEnumerable<User> GetAdultUsers(List<User> users)
{
    foreach (var user in users)
    {
        if (user.Age >= 18)
        {
            yield return user; // فقط کاربران بزرگسال را یکی یکی برمی‌گرداند
        }
    }
}
```

## 4. اجرای مرحله‌به‌مرحله Iterator (پشت صحنه)

مهم‌ترین مفهوم در اینجا **Lazy Evaluation (ارزیابی تنبل)** است.
وقتی شما متدی که `yield return` دارد را صدا می‌زنید، **هیچ کدی درون متد اجرا نمی‌شود!** متد فقط یک "ماشین حالت" (State Machine) را برمی‌گرداند.

اجرا دقیقاً به این شکل است:
1. شما روی خروجی متد `foreach` می‌زنید.
2. کامپایلر متد را صدا می‌زند تا به اولین `yield return` برسد.
3. مقدار را برمی‌گرداند و **متد را در همان خط متوقف (Pause) می‌کند**.
4. در دور بعدی حلقه، متد دقیقاً از **همان خطی که متوقف شده بود** ادامه می‌دهد تا به `yield return` بعدی برسد.
5. این کار تا زمانی که متد تمام شود یا به `yield break` برسد ادامه می‌یابد.

## 5. چرا `return` معمولی در Iterator مجاز نیست؟

اگر در متدی که `yield return` دارد، از `return` معمولی استفاده کنید، کامپایلر خطا می‌دهد:
> *CS1622: Cannot return a value from iterators. Use the yield return statement to return a value, or yield break to end the iteration.*

**دلیل منطقی:**
وقتی شما `return` می‌کنید، یعنی می‌خواهید **یک مقدار مشخص** را به عنوان خروجی متد برگردانید. اما وقتی از `yield` استفاده می‌کنید، خروجی متد شما یک **توالی (Sequence)** است. شما نمی‌توانید همزمان بگویید "خروجی من یک دنباله است" و در وسط کار بگویید "خروجی من این یک عدد خاص است".
برای پایان دادن به یک Iterator بدون برگرداندن مقدار، باید از `yield break` یا رسیدن به پایان طبیعی متد (بدون return) استفاده کنید.

## 6. محدودیت‌های `yield return`

استفاده از `yield` جادویی است، اما محدودیت‌هایی هم دارد:
1. **عدم استفاده در `try-catch`:** شما نمی‌توانید `yield return` را داخل یک بلوک `try-catch` قرار دهید (چون ممکن است exception رخ دهد و وضعیت Iterator خراب شود). اما استفاده در `try-finally` مجاز است.
2. **عدم استفاده در Anonymous Methods و Lambda:** نمی‌توانید `yield` را داخل یک `delegate` یا `() => { }` بنویسید.
3. **پارامترهای `ref` و `out`:** متدهای Iterator نمی‌توانند پارامتر `ref` یا `out` داشته باشند.
4. **بلاک‌های `unsafe`:** در کدهای Unsafe نمی‌توان از Iterator استفاده کرد.

## 7. ارتباط Iterator و `IEnumerable<T>`

بسیاری از مبتدیان فکر می‌کنند `IEnumerable` و `yield` یکی هستند. اینطور نیست!
* **`IEnumerable<T>`** یک **قرارداد (Interface)** است که می‌گوید: "من یک مجموعه هستم که می‌توانی روی من حلقه بزنی".
* **`yield`** یک **ابزار (Keyword)** است که کامپایلر سی‌شارپ از آن استفاده می‌کند تا به صورت خودکار کلاس‌های پیچیده‌ای که `IEnumerable<T>` و `IEnumerator<T>` را پیاده‌سازی می‌کنند، برای شما بسازد.

اگر `yield` وجود نداشت، شما مجبور بودید برای هر متد، یک کلاس جداگانه بسازید، متغیرهای وضعیت (State) را ذخیره کنید و متد `MoveNext()` را دستی پیاده‌سازی کنید! `yield` این دردسر را کاملاً از بین می‌برد.

## 8. نکات پیشرفته: تله‌ی اعتبارسنجی آرگومانها! ⚠️

این بخش برای برنامه‌نویسان متوسط و پیشرفته بسیار حیاتی است.
به دلیل **Lazy Evaluation** (که در بخش ۴ گفتیم)، کد داخل متد Iterator تا زمانی که `foreach` روی آن زده نشود، اجرا نمی‌شود.

### ❌ کد اشتباه:
```csharp
public IEnumerable<int> GetItems(int count)
{
    if (count < 0) 
        throw new ArgumentException("Count cannot be negative"); // این خطا الان پرتاب نمی‌شود!

    for (int i = 0; i < count; i++)
        yield return i;
}
```
اگر این متد را صدا بزنید و `count` منفی باشد، **هیچ خطایی پرتاب نمی‌شود!** چون متد هنوز اجرا نشده است. خطا فقط زمانی پرتاب می‌شود که بخواهید اولین آیتم را بخوانید.

### ✅ راه‌حل حرفه‌ای (تکنیک دو متدی):
برای حل این مشکل، اعتبارسنجی را در یک متد معمولی انجام دهید و Iterator را در یک متد داخلی (یا جداگانه) قرار دهید:

```csharp
public IEnumerable<int> GetItems(int count)
{
    // 1. اعتبارسنجی آنی (Eager Evaluation)
    if (count < 0) 
        throw new ArgumentException("Count cannot be negative");

    // 2. فراخوانی متد Iterator
    return GetItemsIterator(count);
}

private IEnumerable<int> GetItemsIterator(int count)
{
    for (int i = 0; i < count; i++)
        yield return i;
}
```
*نکته: در سی‌شارپ ۸ به بعد و با استفاده از Local Functions می‌توانید این کار را تمیزتر انجام دهید.*
