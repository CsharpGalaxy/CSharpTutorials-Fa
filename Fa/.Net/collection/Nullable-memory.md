## مقدمه: چرا به Nullable نیاز داریم؟
در #C ما دو دسته اصلی تایپ داریم:
1. **Reference Types (انواع مرجعی):** مثل `string` یا `class`. متغیرهای این نوع در واقع یک **اشاره‌گر (Pointer)** به محل داده‌ها در حافظه (Heap) هستند. اگر داده‌ای وجود نداشته باشد، این اشاره‌گر به `null` (هیچ‌کجا) اشاره می‌کند.
2. **Value Types (انواع مقداری):** مثل `int`, `bool`, `DateTime`. این تایپ‌ها **خودِ داده** هستند و مستقیماً مقدار را در خود نگه می‌دارند. 

**مشکل اینجاست:** یک متغیر `int` همیشه باید یک عدد داشته باشد (مثلاً `0`). اما در دنیای واقعی (مثلاً هنگام ارتباط با دیتابیس)، ممکن است بخواهیم بگوییم "سن این کاربر **نامشخص** است" (یعنی اصلاً عددی وجود ندارد، نه حتی صفر). 
چون `int` یک Value Type است، نمی‌تواند `null` شود. راه‌حل #C برای این مشکل، استفاده از **`Nullable<T>`** است.

## مفاهیم پایه (سطح مبتدی)

شما می‌توانید هر Value Type را با اضافه کردن یک `?` به انتهای آن، Nullable کنید.
```csharp
int? age = null; // این یعنی age می‌تواند یک عدد باشد، یا اصلاً مقداری نداشته باشد
```

### نقش HasValue و Value
وقتی با یک متغیر Nullable کار می‌کنید، دو_PROPERTY_ بسیار مهم در اختیار دارید:

* **`HasValue`**: یک `bool` است که به شما می‌گوید آیا این متغیر یک مقدار معتبر دارد یا خیر.
* **`Value`**: مقدار واقعی را برمی‌گرداند.

```csharp
int? age = null;

if (age.HasValue)
{
    Console.WriteLine($"سن کاربر: {age.Value}");
}
else
{
    Console.WriteLine("سن کاربر ثبت نشده است.");
}
```
⚠️ **هشدار مبتدیان:** اگر `HasValue` برابر با `false` باشد و شما سعی کنید `age.Value` را بخوانید، برنامه با خطای `InvalidOperationException` مواجه می‌شود (چون مقداری برای خواندن وجود ندارد).

## کالبدشکافی ساختار داخلی (سطح پیشرفته)

حالا بیایید کلاه مهندسی معکوس را بر سر بگذاریم و ببینیم `Nullable<T>` در دل #C و CLR چگونه پیاده‌سازی شده است.

### ساختار Nullable در دل CLR
تایپ `Nullable<T>` در واقع یک **Struct** است. اگر به [سورس کد اصلی .NET](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Nullable.cs) نگاه کنید، ساختار آن تقریباً به شکل زیر است:

```csharp
public struct Nullable<T> where T : struct
{
    private readonly bool hasValue; // آیا مقداری وجود دارد؟
    internal T value;               // خودِ مقدار

    // ... متدها و Constructor ها
}
```
**نکته کلیدی:** چون `Nullable<T>` خودش یک `struct` (Value Type) است، **هرگز نمی‌تواند `null` واقعی باشد!** 

### راز وجود Value حتی در حالت Null!
این بخش، جذاب‌ترین قسمت ماجراست. شما در کد می‌نویسید `int? x = null;`. اما در حافظه چه اتفاقی می‌افتد؟

وقتی شما `x` را `null` می‌کنید، در واقع `hasValue` روی `false` تنظیم می‌شود. اما فیلد `value` **از بین نمی‌رود و خالی نمی‌ماند**. چون `Nullable<T>` یک Struct است، حافظه برای آن رزرو شده است. در این حالت، فیلد `value` مقدار **پیش‌فرض (Default)** تایپ `T` را در خود نگه می‌دارد.

* اگر `int? x = null;` باشد، در حافظه `x.value` برابر با `0` است.
* اگر `bool? y = null;` باشد، در حافظه `y.value` برابر با `false` است.

**نتیجه‌گیری عمیق:** وقتی یک Nullable مقدار `null` دارد، در سطح حافظه، `Value` وجود دارد (با مقدار پیش‌فرض تایپ خودش)، اما این `HasValue` است که به CLR و برنامه‌نویس می‌گوید: **"به این مقدار کاری نداشته باش، این متغیر در دنیای بیرون Null است!"**

## حافظه و Storage (نحوه ذخیره‌سازی)

### محل زندگی در Stack و Heap
* **حالت عادی:** چون `Nullable<T>` یک Struct است، مانند سایر Value Types معمولاً در **Stack** (پشته) ذخیره می‌شود (مگر اینکه فیلد یک کلاس باشد یا Boxing شود).
* **اشغال حافظه (Memory Footprint):** بیایید محاسبه کنیم یک `Nullable<int>` چقدر فضا می‌گیرد؟
  * `bool hasValue` = 1 بایت
  * `int value` = 4 بایت
  * **مجموع = 5 بایت؟** ❌ خیر!
  * به دلیل پدیده‌ای به نام **Struct Padding و Memory Alignment** در CLR، حافظه باید مضربی از 4 (یا 8) باشد. بنابراین کامپایلر 3 بایت فضای پرت (Padding) اضافه می‌کند تا `value` در لبه‌های استاندارد حافظه قرار گیرد. در نتیجه، یک `Nullable<int>` در حافظه **8 بایت** فضا اشغال می‌کند.

### پدیده Boxing در Nullable
اگر یک `Nullable<T>` را به یک متغیر `object` نسبت دهید (Boxing)، CLR یک رفتار هوشمندانه و عجیب نشان می‌دهد:

```csharp
int? nullVal = null;
object boxedNull = nullVal; // نتیجه: null (Reference Null)

int? validVal = 5;
object boxedVal = validVal; // نتیجه: یک int با مقدار 5 روی Heap
```
**قانون طلایی Boxing در Nullable:**
1. اگر `HasValue == false` باشد، CLR به جای باکس کردن Struct، یک **Reference Null** واقعی تولید می‌کند.
2. اگر `HasValue == true` باشد، CLR فقط فیلد `T` (مثلاً `int`) را باکس می‌کند، نه خودِ Struct را.

## تفاوت Null واقعی، مقدار پیش‌فرض و Nullable خالی

برای درک عمیق، این سه مفهوم را با هم مقایسه می‌کنیم:

| مفهوم | مثال | وضعیت در حافظه (Memory) | نوع تایپ |
| :--- | :--- | :--- | :--- |
| **Null واقعی** | `string s = null;` | اشاره‌گر (Pointer) روی `0x00000000` تنظیم شده. هیچ حافظه‌ای برای داده رزرو نشده. | Reference Type |
| **مقدار پیش‌فرض** | `int i = default;` | حافظه رزرو شده (4 بایت). تمام بیت‌ها `0` هستند (مقدار `0`). | Value Type |
| **Nullable خالی** | `int? n = null;` | حافظه رزرو شده (8 بایت). `hasValue` برابر `false` و `value` برابر `0` است. | Value Type (Struct) |

## جمع‌بندی و بهترین روش‌ها

1. **استفاده از `??` و `?.`:** برای خوانایی بهتر و جلوگیری از خطا، همیشه به جای چک کردن `HasValue` از اپراتورهای Null-coalescing (`??`) و Null-conditional (`?.`) استفاده کنید.
   ```csharp
   int finalAge = age ?? 0; // اگر age نال بود، 0 را قرار بده
   ```
2. **مراقب Padding حافظه باشید:** اگر در حال نوشتن کدهای بسیار حساس به پرفورمنس (High-Performance) یا کار با آرایه‌های بزرگ از Structها هستید، استفاده از `Nullable` باعث افزایش مصرف حافظه به دلیل Padding می‌شود.
3. **دیتابیس و ORM:** بهترین و استانداردترین کاربرد `Nullable<T>` در #C، مپینگ کردن فیلدهای دیتابیس است که قابلیت `Allow Null` دارند.
